# AlipanBuddy v1.3.0

界面统一到一套设计语言，外加几个长期存在的功能缺陷修复。

## 设计系统

- **Arco 的变量改由 Material 层定义**（新增 `src/assets/arco-tokens.css`）。此前 Material 只是
  逐个组件覆盖在 Arco 之上，两套系统在每个共用角色上都不一致：Arco 用四种灰色描边对应
  Material 的一种 outline，圆角是 2/4/8px 对 4/8/12px，文字色接近但从不相等。现在组件自己
  就会取到 Material 的形状、表面、文字与描边，不再需要逐条 `!important` 去改。
  - 补齐了 Arco 有、而 Material 层此前没有命名的角色：`surface-container-highest`、
    `outline`、`on-surface-muted`、`on-surface-disabled`、`error` / `error-container`、
    `success` / `success-container`。
- **样式加载顺序修正**：`main.ts` 此前先引入 `App.vue`（它会带入 `global.css`、`antd.css`
  以及全部 68 个全局组件样式块），再引入框架样式，导致应用自己的 CSS 在同优先级下永远输给
  Arco —— 这正是几百条 `!important` 的来源。现在是框架 → 令牌桥接 → 应用样式。
- **基础主题换回 Arco 官方版**。此前使用的 `@arco-themes/vue-gi-demo` 硬编码了 45 处圆角和
  24 个颜色字面量，令牌桥接无法覆盖；官方主题有 90 处圆角走令牌。
- **红色只用于危险操作**。文件列表上方的五条说明（"列出已标记的文件…"、"免费=10天…"）
  原本是内联 `color: crimson`，既不是警告、也不跟随主题，现已改为跟随主题的次要文字色；
  "该操作不可逆"这类确实危险的提示保留红色，但改从 `--md-error` 取值。

## 菜单

- **新建 / 上传等操作菜单不再出现滚动条**。`PanRight.vue` 里遗留了一条
  `max-height: 300px !important`，压过了 v1.1.0 声称已经解除的高度上限，导致菜单在任何窗口
  尺寸下都要滚动。移除后菜单按内容自适应（680px 窗口下有 473px 可用高度）。
- **修正菜单里那条一直都在的滚动条**。Arco 的虚拟滚动条只在弹层尚未完成布局时测量一次
  "是否可滚动"，此后不再更新，于是放得下的菜单也会带一条满高的滑块，鼠标移入就淡入。
  弹层改用浏览器原生滚动条 —— 真正需要时才出现，且已与应用其它滚动条同一套样式。

## 插件页

- 步骤标题此前把序号写成 `"1:"` 前缀，于是没有序号的小节就留下一个孤零零的冒号
  （`:注意事项`、`:为什么要加密？` 等 7 处）。序号改为圆形徽标，冒号全部去掉。
  加密流程的编号也重新排过：原本跳过了"加密或解密"这一步、从 0 开始、并且在每个分支里
  重新计数，现在按当前分支连续排 1..7。
- 正文里 10 处 Arco 调色板的绿色 / 红色文字：真正表示状态的（格式"已测试通过"/"测试失败"）
  保留颜色但改从令牌取值，其余是叙述性文字，恢复为正常文本。

## 修复

- **拖动文件到目录树 / 快捷方式不生效**。`dragstart` 设置了拖拽图像却从未调用 `setData`，
  拖拽数据区为空。Chromium（Electron 时代）照样能完成拖放，WebKit 则会触发 dragenter /
  dragover 但不允许任何目标接受 drop —— 这是迁移到 Tauri 后遗留的问题。
- **"关闭时退出"时进程仍然存在**。只有应用自带的关闭按钮会读取该设置（它经由渲染层
  发送 `exit`）；Alt+F4、窗口管理器关闭、注销登录等走的是 Rust 的 `CloseRequested`，
  而那里无条件地阻止关闭并隐藏窗口。于是"用 X 关闭会退出、用别的方式关闭不会退出"，
  看起来就像是偶发。两条路径现在读取同一个设置。
